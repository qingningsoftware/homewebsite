# 青柠软件官网重设计 — 设计稿

日期：2026-11-20（修订：2026-11-21 增补 §12 留言墙）
状态：待确认（供审阅，批准后进入实施计划）

---

## 1. 背景与目的

旧官网（`web1/`）为 Flutter Web 编译产物，**源代码已丢失**，无法维护。更致命的是：正文全部埋在 `main.dart.js` 里，搜索引擎和 AI 爬虫几乎抓不到任何内容——对一家靠官网获客的软件公司，等于在 AI 时代隐身。

新站在 `src/` 从零重建，三个核心诉求：

1. **GEO（生成式引擎优化）**：让搜索引擎和 AI（ChatGPT、Perplexity、Claude 等）能抓取、理解并引用站点内容。
2. **设计个性**：拒绝市面上千篇一律的公司官网模板感，形成鲜明的品牌记忆点。
3. **内容重构**：产品主打**智慧社区平台**与**远程医疗 PACS**；服务内容扩充；新增 **AI Agent 开发**板块；介绍文案复用旧站资产。

## 2. 目标 / 非目标 / 反目标

**目标**
- 纯静态直出 HTML（服务端渲染的构建产物），部署到现有 Nginx 服务器即可，无运行时后端。
- 每个产品一个独立权威页面，内容结构化为「是什么 / 给谁用 / 核心功能 / 部署方式 / FAQ」。
- 结构化数据齐全（JSON-LD）、`llms.txt`、`sitemap.xml`、`robots.txt`。
- 暗色终端科技风贯穿全站，交互有个性和记忆点。
- 复用旧站全部可迁移的文案与图片资产。

**非目标**
- 不做后台 CMS——内容以 Markdown/数据文件管理，改内容即改文件重新构建。
- 不做真·大模型接入（列为可选二期，见 §10）。
- 不做联系表单（静态站无后端；用电话 / 微信二维码 / QQ / mailto 替代）。
- 不做联网留言板——「留言墙」为纯本地存储方案，不引入任何后端（§12）。
- 不做多语言版本。

**反目标（出现即算失败）**
- 内容藏在 JS 里导致 AI 抓不到（重蹈旧站覆辙）。
- boot 动画或打字机效果慢到让访客流失（所有动效短、可跳过、尊重 `prefers-reduced-motion`）。
- 为了花哨牺牲信息可读性——客户（物业、医院、政府）要能 3 秒内找到电话。

## 3. 方案取舍

**技术栈：Astro（静态站点生成器）**
- 候选一：纯手写 HTML/CSS——零依赖，但 10 个页面的公共部分（状态栏、页脚）无法组件化，维护差。弃。
- 候选二：Next.js/Nuxt SSG——能力过剩，带运行时概念，构建链重。弃。
- **选定 Astro**：默认输出零 JS 的纯静态 HTML（对本项目最重要）、组件化布局、内容集合（Markdown 写产品/服务文档）、构建产物直接扔 Nginx。

**展示骨架：终端会话 + 日志流**
- 候选：tmux 分屏工作台（信息密度高、移动端难做）、伪 OS 桌面（工作量最大、对医院/政府客户偏玩具感）。
- **选定终端会话 + 日志流**：个性最强且信息好读，与「软件公司」身份同构。

**视觉风格：暗色终端科技风**
- 深色底 + 青柠绿荧光强调——「青柠」品牌名即视觉签名。

**字体**
- 标题与代码感元素：等宽字体栈 `ui-monospace, 'JetBrains Mono', 'Fira Code', Consolas, monospace`（不加载 webfont，用系统等宽栈保证速度；如需品牌一致性再考虑子集化加载 latin 字重）。
- 中文正文：系统黑体栈（`-apple-system, 'PingFang SC', 'Microsoft YaHei', sans-serif`），等宽标题 + 黑体正文的混排是本站的基本节奏。

**终端质感细节**
- 面板 = 终端窗口：左上 `● ● ●` 圆点 + 等宽标题（`$ zhsq deploy`）。
- 全站极低透明度扫描线/CRT 纹理背景（`opacity ≤ 0.03`，不干扰阅读）。
- 光标 `▊` 闪烁、行 hover 高亮（背景 `#1C1C1F`）。
- 状态符：`✓` 绿 / `!` 黄 / `✗` 红。
- 动效统一走 CSS + IntersectionObserver，进场触发一次不重复；`prefers-reduced-motion` 下全部直接显示。

## 6. 首页骨架（自上而下）

1. **Boot 层**：进站 0.8s 黑屏逐行文字（`QN-OS v3.0 initializing ... OK` / `loading: 社区 医疗 支付 agent ... OK`），点击/任意键/自动均可跳过；`sessionStorage` 记录，同会话二次访问不重播。
2. **Hero = 伪命令行**：预置一条提问被逐字打出（`~ ❯ 谁是青柠软件`），下方本地「执行」输出一句话定位（专注智慧社区与医疗影像的软件研发团队）；其下是一条**真的可输入的命令行**，本地关键词匹配（`products` `pacs` `agent` `services` `about` `contact` `help` `ls` `clear`，未知命令输出幽默提示 + 相似命令建议）。移动端命令行收纳为菜单按钮，功能等价。
3. **两大产品 = 部署会话回放**：智慧社区、PACS 各一个终端窗口面板，滚动进入视口时逐行打字机输出（`✓ 多厂家设备接入 ..... 刷卡/二维码/人脸` / `✓ 微信小程序 ..... 已上线`），末行 `→ 查看详情`。
4. **其余产品 = 进程列表**：`ps aux` 风格等宽表格，一行一个（PID 列换成上线年份），不抢主打的戏。
5. **Agent 板块预告 + 迷你留言墙**（同带并排，约 2:1）：左侧为一段静态回放的 Agent 对话（用户提问 → `◆ 思考中` → `调用工具 search_services()` → 结果卡片），CTA `→ /agent/`；右侧为迷你留言墙区块（约 390px，live 轮播最新留言 + 青柠按钮入口，详见 §12.2）。
6. **数据行**：`uptime 10年 · 软著 10项 · 解决方案 6套 · Gitee 开源`（sysmon 风格等宽数据条）。
7. **tmux 状态栏**（`position: fixed` 底部，全站常驻）：左 `[0:qn-主站]` + 当前页名，中间导航链接（产品/服务/Agent/留言墙/关于/联系），右侧绿点 + ICP 备案号入口。移动端转为顶部简化栏 + 底栏导航。

## 7. 内页模式

- **产品页（通用模板）**：man 手册结构——`NAME`（名称+一句话）/ `SYNOPSIS`（适用对象与部署形态）/ `DESCRIPTION`（详细描述，复用旧文案扩写）/ `FEATURES`（`$ qn --features` 输出的功能清单）/ `FAQ`（3–5 条，同时渲染为页面可见内容 + JSON-LD FAQPage）/ 底部 CTA（电话 + 微信二维码）。
  - 智慧社区页：标题用品牌名「智尚通行 · 智慧社区平台」（已确认），重点覆盖多厂家设备接入（刷卡/二维码/人脸）、微信小程序、物业/厂商/代理商三种角色。
  - PACS 页重点：多级医院电子影像网上诊断、纯 Web、可私域或公网部署。
- **服务页**：8 项服务卡片化目录（终端窗口面板样式），每项含「做什么 / 技术栈 / 交付物」。
- **Agent 页**：见 §9.3。
- **关于页**：公司简介（复用旧站 aboutdetail 文案）+ 软著证书墙（10 张，等宽文件名标签 + 图片）+ 发展时间线（`[2016] 公司成立` 日志格式，重要事件逐年排列）。
- **联系页**：电话 / 邮箱 / 地址（河北省石家庄市裕华区河北地质大学综合楼）/ 企业微信·QQ·小红书二维码（图片迁移）/ Gitee 链接；页面呈现为 `contact --info` 命令输出。
- **留言墙页**：随机散布终端卡片墙，公开浏览、匿名留言与匿名回复（仅存访客本机），完整设计见 §12。

## 8. GEO 方案（AI 可抓取）

1. **零 JS 直出**：Astro 构建产物为完整静态 HTML，所有正文不依赖客户端渲染——AI 爬虫与旧搜索引擎都能直接读到全文。
2. **JSON-LD 结构化数据**：
   - 首页 `Organization`（名称、地址、电话、logo、sameAs：Gitee/GitHub）+ `WebSite`
   - 每产品页 `Product`（name/description/brand）+ `FAQPage`
   - 服务页 `Service` 列表
3. **`/llms.txt`**：站点简介、公司一句话定位、6 个产品与 8 项服务的清单及一句话描述、关键页面链接——AI 引擎的「导读文件」。
4. **`/robots.txt`**：显式允许主流 AI 爬虫（GPTBot、ClaudeBot、PerplexityBot、Google-Extended、Bytespider 等）+ `Sitemap:` 引用。
5. **语义化 HTML**：`header/nav/main/article/section/footer`、严格 h1→h3 层级、每页唯一 `title`/`description`/`canonical`、Open Graph 标签。
6. **内容可摘录性**：每页含直接回答「X 是什么」「X 能解决什么问题」的段落，方便 AI 引用时原样摘录。
7. **性能即 GEO**：无框架 JS、图片 `loading="lazy"` + 显式宽高、内联关键 CSS——AI 与搜索都偏好快站。
8. **百度统计**：全站唯一第三方脚本（异步加载），用于验证搜索与 AI 引擎的来源流量。

## 12. 留言墙（2026-11-21 增补定稿）

### 12.1 定位

目的：**给网站增加互动氛围**，不是真实的客户反馈渠道。访客能看、能匿名写、能匿名回复；所有留言只保存在访客自己的浏览器（localStorage），不经过任何服务器——全站仍然零后端。对外叙事：「留言不经过任何服务器，连我们自己都看不到」。

- 目标：好看、有科技感动效、诚实（不假装联网）。
- 非目标：无后端、无审核后台、无通知、无管理界面、不是客服渠道（页面引导商务需求去 `/contact/`）。
- 反目标：发送后谎称「已提交，大家都能看到」——文案必须写明仅本机保存。

### 12.2 入口

1. **首页迷你留言墙区块（主入口）**：与 §6.5 Agent 板块预告同带并排，宽约 390px（不与左侧平分）：
   - 标题：伪命令 `watch -n3 tail -3 /wall/msgs.log` 逐字打出 + 绿点闪烁（live 感）；
   - 内容：墙上最新 3 条留言的迷你卡片，SSR 直出；JS 每 3 秒让一条新留言从顶部「落进」、最旧的淡出下沉，循环轮播全部预置留言；
   - 卡片带随机小角度（±2.5°）、悬停扶正发光；背景一条极淡扫光线（6s/轮）+ 3–4 粒光尘上浮；
   - 底部 CTA：**青柠实底按钮「→ 进入留言墙」**（13px 加粗、深色字，2.8s 呼吸辉光，悬停提亮上浮），右侧次要文字「共 N 条信号」。
   - **数字与本机状态联动**：SSR 默认「共 12 条信号」；有 JS 时读取 localStorage 修正为「预置 + 本机」的真实总数，轮播内容同样混入本机留言——首页如实体现在墙上的全部信号（呼应 §12.1 诚实目标）。
2. **tmux 状态栏**（§6.7）导航加「留言墙」普通链接（保底入口）。
3. 已评审废弃的方案（防返工）：状态栏未读徽章、命令行 `wall` 命令、全站信号灯浮标、全宽预告条。

### 12.3 `/wall/` 页面：随机散布卡片墙

- 卡片 = 终端窗口样式（`● ● ●` + 文件名标题），一条留言一张卡；回复以缩进日志行挂在卡内（仅一层深度，回复的回复并列为同一卡的追加行）。
- 「广播」卡（公司动态改写的留言体）用黄色标签区分。
- **散布布局**：构建时用固定种子的伪随机数生成每张卡的位置/角度/尺寸，直出进 HTML；风格取「更乱」——角度 ±6°、允许边缘轻叠、尺寸差异明显；每次重新构建换一副布局，同一构建产物所有人看到相同 HTML（SEO 稳定、无 CLS）。
- **动效**：滚动进场时卡片逐张「落钉」（自上而下带角度落定，间隔约 0.15s，IntersectionObserver 触发一次不重复）；待机时每张卡以不同周期极缓慢浮动（±5px）；悬停扶正（角度归零）+ 上浮 + 青柠辉光。
- **留言框**：墙中央一张虚线边框卡片 `$ wall --write`，含输入框与发送按钮，说明文字「匿名 · 仅保存在你的浏览器，不经过服务器」；旁给 `/contact/` 入口引导商务需求。
- **手机端**：散布退化为纵向瀑布流（保留落钉进场，不做绝对定位散布）。
- **空间模型（预置 + 本机两层）**：散布区只排预置卡，画布高度随内容增长（非固定视口）；访客本机留言统一落在墙尾「`~/my-messages` 本机留言区」——纵向网格、卡片保留角度/浮动/悬停动效，无本机留言则整区不渲染；发送后平滑滚动定位到新卡，让用户看到落钉动效。本机留言上限 30 条，超出提示先删几条。

### 12.4 本地留言行为

- 提交：写入 localStorage（key `qn-wall-messages`），新卡片以落钉动效插入墙中，刷新后仍在；换设备/清浏览器缓存即消失（页面文案如实说明）。
- 匿名：不收集任何信息，无昵称字段，统一显示「匿名」。
- 回复：对任意卡片（含自己刚发的）可回复，回复以缩进行追加到该卡内，同样仅存本机。
- 输入上限 200 字，超长截断提示（防布局爆炸）。
- 删除：本机留言卡悬停显示「×」可单条删除，本机区页脚提供「清空我的留言」；localStorage 中本机条目带 id、与预置条目区分。
- 时间戳：预置卡用**绝对日期**（如 `[2026-11-21]`），杜绝静态站上「刚刚」挂三个月的假相对时间；本机卡用运行时真实计算的相对时间（刚刚 / N 天前）。
- 不发起任何网络请求。

### 12.5 内容口径与数据文件

- **预置留言数据文件化**：全部预置留言放 `src/data/wall-messages.json`，Astro 构建时读取、直出进 HTML。每条含 id / 类型（广播 | 打卡）/ 正文 / 日期 / 回复数组；公司侧后期直接编辑该文件（增、删、改）后重新构建发布，不碰页面代码。
- **容量预留 100 条**：初始起草约 12 条，数据文件与散布墙按 100 条容量设计——画布高度随条数自动增长、防重叠算法按条数扩展；待机浮动只对视口内卡片启用（性能护栏）。
- 首页徽标「共 N 条信号」N = JSON 条数（有本机留言时按 §12.2 修正为真实总数）。
- 两类混搭：
  1. 公司「广播」：真实信息改写留言体（产品动态、开源更新；招聘类仅在确认真实在招信息后写入，可用「欢迎投递简历至联系邮箱」模糊表述，不虚构岗位），黄色 `[广播]` 标签；
  2. 打卡氛围向访客留言（「石家庄老乡报道」「这配色很上头」一类）。
- 预置 12 条的最终文案按 §11 惯例随实现起草、交付时一并确认；公司若想提供真实「老乡/打卡」式留言，起草前告知。
- 禁止虚构具体客户好评（假背书）；不使用 §9 定性口径之外的数字；模板作者遗留个人信息剔除规则同样适用。

### 12.6 技术与降级

- Astro 静态直出：散布坐标、卡片内容、首页迷你墙首屏 3 条均为构建时生成，正文零 JS 依赖；轮播/浮动/落钉等动效为渐进增强（少量内联 JS）。
- `prefers-reduced-motion`：全部动效（落钉、浮动、轮播、辉光、扫光、粒子）停止，静态完整呈现。
- GEO：`/wall/` 有独立 title/description/canonical；留言正文为服务端直出 HTML；无额外 JSON-LD（UGC 无引用价值，页面本身可索引）。
- 留给实施阶段：随机种子与函数选型（如 mulberry32）、散布防重叠策略、移动端断点、轮播容器的 aria 属性取值。
